## 为什么用磁盘上的 Markdown

简历住在 `src/translations.ts`
里,和界面文案放在一起:一份手工译成七种语言的文档,每一条字符串都由代码测量并适配。文章正相反——长篇散文,既不受类型检查,也不被测量,而且还会不断增加。我不希望每发表一篇,打包体积就长一截,更不希望一个笔误让编译失败。于是内容住在磁盘上,由构建在预渲染时读取。代码归代码,散文归散文。

## 文件系统就是数据

一篇文章的地址只有两段:文件夹是
slug,文件名是语言。`content/posts/comment-ecrire-un-article/zh.md`
就是你正在读的这一页;旁边的 `en.md`
是它的英文版。没有对照表,也没有注册表:翻译就是在旁边放一个文件,撤掉一种语言就是删掉一个文件。那条规则——一篇文章存在于一到
n
种语言中,每份索引只列出自己这门语言里确实存在的——不可能因为遗忘而被违反。`shanghai-note`
就是明证:它只有中文,所以西班牙语读者永远不会在自己的索引里看到它;而从中文页面出发,语言切换器会把人送到各语言的索引,而不是一个死链接。这篇文章则相反,七种语言俱全。

## 无依赖的渲染

渲染用的是 `Bun.markdown`,Bun 内建的 GFM
引擎:整个项目一共只有两个依赖,博客一个渲染依赖也没有再添。分两步——`Bun.markdown.html()`
产出 HTML,随后 `HTMLRewriter` 补上它不做的事:标题锚点、外链的
`rel`、可横向滚动的表格、惰性加载的图片,以及中文片段的 `lang` 标记。

## 英文在根目录

英文住在站点根目录,其余每种语言各占一个文件夹:英文是 `/blog/…`,这一版是
`/zh/blog/…`。资源路径按每一页的深度计算,始终保持相对:`dist/`
可以原封不动地放到任何前缀之下,不必重新构建。只有做搜索引擎优化的绝对 URL
会在部署时接上域名。

## 那道防线,不多也不少

`Bun.markdown` 会放过原始
HTML。逐个封堵已知标签就是一份黑名单,从结构上说永远是开着的;所以构建用的是一份封闭的白名单:只有合法
Markdown 会产出的标签才能通过,其余一律拒绝,无论是否见过。任何 `on…`
属性都过不去。每个 `href` 或 `src` 在实体解码、并剔除足以伪装 `javascript:`
的控制字符之后,必须是
`http`、`https`、`mailto`,或者干脆是相对路径;没能解析的实体一律拒绝,因为浏览器可是会解析它的。

它不保证的是:既非事件处理器也非 URL
的属性不受检查。这不是一个通用的净化器,而是围着「一篇文章可以产出什么」筑起的一道篱笆——而这篇文章本身就通过了自己的过滤器,这正是要点。

## 手册

写一篇文章,就是建一个文件:

```text
content/posts/<slug>/<lang>.md
```

slug
由小写字母、数字和连字符组成。有些名字是保留的,因为它们已经指向站点的某个文件或文件夹:`assets`、`blog`、`cv`、`index`、`404`、`robots`、`sitemap`、`feed`、`og-image`,以及各语言代码——一篇叫
`zh` 的文章会盖掉该语言的文件夹。

frontmatter 是 YAML,读它的是 `Bun.YAML.parse`——语法由 Bun
负责,所以你写的就是你在别处一直写的那种 YAML。构建负责的是契约:`title` 和 `date`
必填,其余可选,任何未知或重复的键都会被拒绝,并指名是哪个文件。一个完整的例子:

```text
---
title: 怎样写一篇文章
date: 2026-08-09
summary: 这篇文章承诺了什么,一句话说清。
tags: [meta, web]
---
```

逐字段来说:`date` 是一个真实存在的 `YYYY-MM-DD`
日期——二月三十一日会被拒绝;`summary` 若不写,会从正文推导;`tags` 写成
`[a, b]`;`draft: true` 会把文章排除在外,除非 `DRAFTS=1`;`updated`
用来标注修订日期。

想按真实 URL 阅读文章——开发服务器并不知道博客的那些地址:

```bash
bun run preview           # 构建,然后在 http://localhost:4173 提供服务
PORT=8080 bun run preview # 换一个端口
DRAFTS=1 bun run preview  # 包含草稿
```

字体不必操心:推送到 `main` 之后,有一个工作流会重新为站点的 Noto
生成子集并提交文件。若想在推送前就看到文章真实的字形:

```bash
bun run fonts:update
```

子集里缺一个字形,页面上就是一个豆腐块;而构建会拒绝产出覆盖不全的
`dist/`——所以忘记这一步是一次响亮的失败,绝不会变成读者屏幕上的意外。

最后是 `zh-hk` 的规则:写好 `zh-hant.md`
就够了——香港版由站点的词汇表从台湾版投影而来,而显式的 `zh-hk.md`
优先。干巴巴的约定住在 `AGENTS.md` 里;这篇文章是叙述,那个文件是参考。
