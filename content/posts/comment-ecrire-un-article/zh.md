## 为什么把 Markdown 放在磁盘上

简历住在 `src/translations.ts`
里,和界面文案挨着:一份文档,手工译成七种语言,每一条字符串都由代码测量、适配。文章正相反——长篇散文,既不受类型检查,也不被测量,而且还会不断增加。我不希望每发一篇文章打包体积就涨一分,也不希望一个错字让编译失败。于是内容住在磁盘上,由构建在预渲染时读取。代码归代码,散文归散文。

## 文件系统就是数据

一篇文章的地址只有两段:文件夹是
slug,文件名是语言。`content/posts/comment-ecrire-un-article/zh.md`
就是你正在读的这一页,旁边的 `en.md`
是英文版。没有对照表,也没有登记簿:翻译就是在旁边放一个文件,撤掉一种语言就是删掉一个文件。那条规则——一篇文章存在于一到
n
种语言,每份索引只列出本语言里确实存在的——不可能因为疏忽而被违反。`shanghai-note`
就是明证:它只有中文版,所以西班牙语读者永远不会在自己的索引里见到它;而从中文页出发,语言选择器会把读者带往其他各语言的索引,而不是一个死链。至于本文,七种语言里都有。

## 零依赖的渲染

渲染交给 `Bun.markdown`,Bun 原生的 GFM
引擎:整个项目一共只有两个依赖,博客一个渲染依赖也没有再添。两步——`Bun.markdown.html()`
产出 HTML,再由 `HTMLRewriter` 补上它不做的事:标题锚点、外链的
`rel`、可横向滚动的表格、惰性加载的图片,以及中文片段的 `lang` 标记。

## 英语在根目录

英语住在根目录,其余每种语言各占一个文件夹:英文版在 `/blog/…`,本文在
`/zh/blog/…`。资源路径依据每一页的深度计算,始终是相对的:`dist/`
可以原样放到任何前缀之下,无需重新构建。只有用于收录的绝对 URL
会在部署时补上域名。

## 那道护栏,不多也不少

`Bun.markdown` 会放行原始
HTML。逐个封禁已知标签是一份黑名单,天生是开放的;所以构建采用一份封闭的白名单:只有合法
Markdown 会产生的标签才通过,其余一律拒绝,无论是否见过。任何 `on…`
属性都不放行。每一个 `href` 或 `src`,在解码实体、剥掉那些用来伪装 `javascript:`
的控制字符之后,都必须是 `http`、`https`、`mailto`
或相对路径;没能解析出来的实体一律拒绝,因为浏览器是会解析它的。

它不保证的部分:既非事件处理器也非 URL
的属性不受检查。这不是通用的净化器,而是围着「一篇文章可以产出什么」筑起的一道栅栏——而本文本身就通过了自己的过滤器,这正是要点。

## 手册

写一篇文章,就是建一个文件:

```text
content/posts/<slug>/<lang>.md
```

slug
由小写字母、数字和连字符组成。有些名字被保留,因为它们已经指向站点的某个文件或文件夹:`assets`、`blog`、`cv`、`index`、`404`、`robots`、`sitemap`、`feed`、`og-image`,以及各语言代码——一篇叫
`zh` 的文章会覆盖掉该语言的文件夹。

frontmatter 就是 YAML,由 `Bun.YAML.parse` 负责读取——语法是 Bun
的,所以你照着别处的写法写就行。构建负责的是契约:`title` 和 `date`
必填,其余可选,任何未知或重复的键都会被拒绝,并指名是哪个文件。一个完整的例子:

```text
---
title: 怎样写一篇文章
date: 2026-08-09
summary: 这篇文章要讲什么,一句话。
tags: [meta, web]
---
```

逐个字段来说:`date` 必须是真实存在的 `YYYY-MM-DD` 日期——2 月 31
日会被拒绝;`summary` 缺省时从正文推导;`tags` 写作 `[a, b]`;`draft: true`
会让文章不被发布,除非 `DRAFTS=1`;`updated` 用来标注修订日期。

想按真实 URL 阅读文章——开发服务器并不知道博客的地址:

```bash
bun run preview           # 先构建,再在 http://localhost:4173 提供服务
PORT=8080 bun run preview # 换个端口
DRAFTS=1 bun run preview  # 包含草稿
```

写完之后,还有一条命令:

```bash
bun run fonts:update
```

它会重新对站点的 Noto
字体做子集化:子集里缺少的字形会显示成豆腐块——这种错误往往只有在读者的屏幕上才被发现。

最后是 `zh-hk` 规则:写 `zh-hant.md`
就够了——香港版由站点的词汇表从台湾版投影而来,而显式的 `zh-hk.md`
优先。干巴巴的约定住在 `AGENTS.md` 里;本文是叙述,那个文件才是参考。
