## 為什麼把 Markdown 放在磁碟上

履歷住在 `src/translations.ts`
裡,和介面文案挨著:一份文件,手工譯成七種語言,每一條字串都由程式碼量測、調整。文章正相反——長篇散文,既不受型別檢查,也不被量測,而且還會不斷增加。我不希望每發一篇文章打包體積就漲一分,也不希望一個錯字讓編譯失敗。於是內容住在磁碟上,由建置在預先算繪時讀取。程式碼歸程式碼,散文歸散文。

## 檔案系統就是資料

一篇文章的位址只有兩段:資料夾是
slug,檔名是語言。`content/posts/comment-ecrire-un-article/zh-hant.md`
就是你正在讀的這一頁,旁邊的 `en.md`
是英文版。沒有對照表,也沒有登記簿:翻譯就是在旁邊放一個檔案,撤掉一種語言就是刪掉一個檔案。那條規則——一篇文章存在於一到
n
種語言,每份索引只列出本語言裡確實存在的——不可能因為疏忽而被違反。`shanghai-note`
就是明證:它只有簡體中文版,所以西班牙語讀者永遠不會在自己的索引裡見到它;而從中文頁出發,語言選擇器會把讀者帶往其他各語言的索引,而不是一個死連結。至於本文,七種語言裡都有。

## 零相依的算繪

算繪交給 `Bun.markdown`,Bun 內建的 GFM
引擎:整個專案一共只有兩個相依套件,部落格一個算繪相依也沒有再添。兩步——`Bun.markdown.html()`
產出 HTML,再由 `HTMLRewriter` 補上它不做的事:標題錨點、外部連結的
`rel`、可橫向捲動的表格、延遲載入的圖片,以及中文片段的 `lang` 標記。

## 英語在根目錄

英語住在根目錄,其餘每種語言各占一個資料夾:英文版在 `/blog/…`,本文在
`/zh-hant/blog/…`。資源路徑依據每一頁的深度計算,始終是相對的:`dist/`
可以原樣放到任何前綴之下,無需重新建置。只有用於收錄的絕對 URL
會在部署時補上網域。

## 那道護欄,不多也不少

`Bun.markdown` 會放行原始
HTML。逐個封鎖已知標籤是一份黑名單,天生是開放的;所以建置採用一份封閉的白名單:只有合法
Markdown 會產生的標籤才通過,其餘一律拒絕,無論是否見過。任何 `on…`
屬性都不放行。每一個 `href` 或 `src`,在解碼實體、剝掉那些用來偽裝 `javascript:`
的控制字元之後,都必須是 `http`、`https`、`mailto`
或相對路徑;沒能解析出來的實體一律拒絕,因為瀏覽器是會解析它的。

它不保證的部分:既非事件處理器也非 URL
的屬性不受檢查。這不是通用的淨化器,而是圍著「一篇文章可以產出什麼」築起的一道柵欄——而本文本身就通過了自己的過濾器,這正是要點。

## 手冊

寫一篇文章,就是建一個檔案:

```text
content/posts/<slug>/<lang>.md
```

slug
由小寫字母、數字和連字號組成。有些名字被保留,因為它們已經指向網站的某個檔案或資料夾:`assets`、`blog`、`cv`、`index`、`404`、`robots`、`sitemap`、`feed`、`og-image`,以及各語言代碼——一篇叫
`zh-hant` 的文章會覆蓋掉該語言的資料夾。

frontmatter 就是 YAML,由 `Bun.YAML.parse` 負責讀取——文法是 Bun
的,所以你照著別處的寫法寫就行。建置負責的是契約:`title` 和 `date`
必填,其餘可選,任何未知或重複的鍵都會被拒絕,並指名是哪個檔案。一個完整的例子:

```text
---
title: 怎樣寫一篇文章
date: 2026-08-09
summary: 這篇文章要講什麼,一句話。
tags: [meta, web]
---
```

逐個欄位來說:`date` 必須是真實存在的 `YYYY-MM-DD` 日期——2 月 31
日會被拒絕;`summary` 預設從內文推導;`tags` 寫作 `[a, b]`;`draft: true`
會讓文章不被發佈,除非 `DRAFTS=1`;`updated` 用來標註修訂日期。

想按真實 URL 閱讀文章——開發伺服器並不知道部落格的位址:

```bash
bun run preview           # 先建置,再在 http://localhost:4173 提供服務
PORT=8080 bun run preview # 換個連接埠
DRAFTS=1 bun run preview  # 包含草稿
```

寫完之後,還有一條命令:

```bash
bun run fonts:update
```

它會重新對網站的 Noto
字型做子集化:子集裡缺少的字形會顯示成豆腐方塊——這種錯誤往往只有在讀者的螢幕上才被發現。

最後是 `zh-hk` 規則:寫 `zh-hant.md`
就夠了——香港版由網站的詞彙表從台灣版投影而來,而明確的 `zh-hk.md`
優先。乾巴巴的慣例住在 `AGENTS.md` 裡;本文是敘述,那個檔案才是參考。
